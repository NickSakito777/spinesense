# stm32duino I3C 可行性调研（2026-05-22）

> 3 个独立 agent 并行调研：(1) stm32duino 框架 I3C 生态、(2) ISM6HG256X 库改 I3C 工程量、(3) HAL_I3C API + SETDASA + internal pull-up 代码模板。本笔记是三份报告的综合 + 置信度分级。

## 一句话结论

**可行，且远比预期快**。stm32duino 框架在 STM32U385 上跑 I3C 多颗 ISM6HG256X 预估工程量 28-44 h（≈ 1 周），**5-22 实测 1 天落地 N=5 全 ALL_PASS**。关键加速：stm32duino BSP 直接暴露 `HAL_I3C` API，sketch 内 `extern "C" { #include "stm32u3xx_hal_i3c.h" }` 即可，**根本不需要改 stm32duino/ISM6HG256X 库的传输层**（Path A 估算时未考虑的捷径，见下方 Path C）。

stm32duino 主仓 main 已核对存在原生 I3CBus 库，但本机当前安装的 `STMicroelectronics:stm32@2.12.0` release 尚未带 `libraries/I3C`。今天的 Arduino 路径以 sketch 内直接调用 STM32 HAL_I3C 为主，实测稳定（详见 [[I3C 多颗 IMU bring-up 实操 2026-05-22]] §5b actual code）。手动引入 main 库可作为后续降工程量选项，但已无紧迫性。

**实测 internal pull-up**：N=5 + ~30 cm 飞线配置下 connectivity ALL_PASS，**未加外部上拉**，5-18 笔记的 "marginal 170-246 ns" 估算偏保守。

### [高置信] STM32U385 internal pull-up API 真实名

正确大小写：`HAL_PWREx_EnableI3CPullUp(PWR_I3CPU_PB13)` — 大写 U，宏是具体引脚名

- 函数名：`HAL_PWREx_EnableI3CPullUp`（5-18 笔记里写的 `EnableI3CPullup` 小写 u 是 typo）

### [高置信] stm32duino/ISM6HG256X 库的传输层抽象干净

仓库结构：

```
ISM6HG256X/
├── library.properties           依赖 Wire + SPI（未列 I3C）
├── keywords.txt                 3.8 KB
├── examples/                    I2C/SPI 示例
└── src/
    ├── ISM6HG256XSensor.h       322 行   <-- 传输层在这
    ├── ISM6HG256XSensor.cpp     2852 行  <-- 业务 API 在这
    ├── ism6hg256x_reg.c         ~326 KB  ST 自动生成寄存器层（勿动）
    └── ism6hg256x_reg.h         ~209 KB  ST 自动生成寄存器层（勿动）
```

- ST 标准 driver（`ism6hg256x_reg.c/h`）用 function pointer 抽象（`stmdev_ctx_t { write_reg, read_reg, mdelay, handle }`），transport-agnostic
- C++ wrapper 层只 2 个文件，I²C / SPI 在 `IO_Read/IO_Write` 内部按 `dev_spi != NULL` 二分支
- 加 I3C 第三分支只需 +50-60 行净增

## HAL_I3C 完整初始化代码模板（高置信）

来自 STM32CubeU3 NUCLEO-U385RG-Q I3C example 抽取，PB13/PB14 = I3C2，含 internal pull-up：

```c
I3C_HandleTypeDef hi3c2;

void I3C2_Init_Full(void) {
  /* 1. 启用 PWR 时钟（latch 解锁前提） */
  __HAL_RCC_PWR_CLK_ENABLE();
  HAL_PWREx_EnablePullUpPullDownConfig();   // 解锁 PUCR latch
  HAL_PWREx_EnableI3CPullUp(PWR_I3CPU_PB13); // SCL
  HAL_PWREx_EnableI3CPullUp(PWR_I3CPU_PB14); // SDA

  /* 2. I3C2 时钟源 + 时钟门 */
  RCC_PeriphCLKInitTypeDef p = {0};
  p.PeriphClockSelection = RCC_PERIPHCLK_I3C2;
  p.I3c2ClockSelection   = RCC_I3C2CLKSOURCE_PCLK2;
  HAL_RCCEx_PeriphCLKConfig(&p);
  __HAL_RCC_I3C2_CLK_ENABLE();

  /* 3. GPIO mux：PB13/PB14 → AF6_I3C2，NOPULL（让 PWR_I3CPU 接管） */
  __HAL_RCC_GPIOB_CLK_ENABLE();
  GPIO_InitTypeDef g = {0};
  g.Pin = GPIO_PIN_13 | GPIO_PIN_14;
  g.Mode = GPIO_MODE_AF_PP;
  g.Pull = GPIO_NOPULL;
  g.Speed = GPIO_SPEED_FREQ_VERY_HIGH;
  g.Alternate = GPIO_AF6_I3C2;
  HAL_GPIO_Init(GPIOB, &g);
  HAL_Delay(1);  // 等总线 idle

  /* 4. I3C controller core init（参数抄 ST sensor 例程） */
  hi3c2.Instance = I3C2;
  hi3c2.Mode = HAL_I3C_MODE_CONTROLLER;
  hi3c2.Init.CtrlBusCharacteristic.SDAHoldTime        = HAL_I3C_SDA_HOLD_TIME_0_5;
  hi3c2.Init.CtrlBusCharacteristic.WaitTime           = HAL_I3C_OWN_ACTIVITY_STATE_0;
  hi3c2.Init.CtrlBusCharacteristic.SCLPPLowDuration   = 0x2F;
  hi3c2.Init.CtrlBusCharacteristic.SCLI3CHighDuration = 0x2F;
  hi3c2.Init.CtrlBusCharacteristic.SCLODLowDuration   = 0x2F;
  hi3c2.Init.CtrlBusCharacteristic.SCLI2CHighDuration = 0x00;
  hi3c2.Init.CtrlBusCharacteristic.BusFreeDuration    = 0x13;
  hi3c2.Init.CtrlBusCharacteristic.BusIdleDuration    = 0x5E;
  HAL_I3C_Init(&hi3c2);

  I3C_FifoConfTypeDef fifo = {HAL_I3C_RXFIFO_THRESHOLD_4_4, HAL_I3C_TXFIFO_THRESHOLD_1_4,
                              HAL_I3C_CONTROLFIFO_DISABLE, HAL_I3C_STATUSFIFO_DISABLE};
  HAL_I3C_SetConfigFifo(&hi3c2, &fifo);
  I3C_CtrlConfTypeDef ctrl = {0, 0, DISABLE, DISABLE, DISABLE, DISABLE, DISABLE, DISABLE};
  HAL_I3C_Ctrl_Config(&hi3c2, &ctrl);

  /* 5. SETDASA 单颗示例（IMU0 静态 0x6B → 动态 0x32） */
  static uint8_t  setdasa_data[1] = { (0x32 << 1) };
  static uint32_t ctrlBuf[16];
  static uint8_t  txBuf[16];
  I3C_CCCTypeDef directCCC[] = {
    { 0x6B /*static addr*/, Direct_SETDASA,
      { setdasa_data, 1 }, LL_I3C_DIRECTION_WRITE }
  };
  I3C_XferTypeDef xfer = { {ctrlBuf, 16}, {txBuf, 1}, {NULL, 0} };
  HAL_I3C_AddDescToFrame(&hi3c2, directCCC, NULL, &xfer, 1,
                         I3C_DIRECT_WITHOUT_DEFBYTE_STOP);
  HAL_I3C_Ctrl_TransmitCCC_IT(&hi3c2, &xfer);
  while (HAL_I3C_GetState(&hi3c2) != HAL_I3C_STATE_READY) { }
  HAL_I3C_Ctrl_IsDeviceI3C_Ready(&hi3c2, 0x32, 300, 1000);
}
```

### 扩展到 5 颗 IMU 的 SETDASA 循环（伪代码）

```c
const uint8_t DYN_ADDR[5] = {0x32, 0x33, 0x34, 0x35, 0x36};
const uint8_t TA0_GPIO[5] = {/* GPIO pin for each IMU's TA0 line */};

for (int i = 0; i < 5; i++) {
  // 1. 只把第 i 颗的 TA0 拉高（其余拉低）→ 该 IMU 静态地址变成 0x6B
  for (int j = 0; j < 5; j++)
    HAL_GPIO_WritePin(TA0_PORT, TA0_GPIO[j],
                      (i == j) ? GPIO_PIN_SET : GPIO_PIN_RESET);
  HAL_Delay(1);
  // 2. 对静态 0x6B 发 SETDASA，赋动态地址 DYN_ADDR[i]
  setdasa_data[0] = DYN_ADDR[i] << 1;
  HAL_I3C_AddDescToFrame(...); HAL_I3C_Ctrl_TransmitCCC_IT(...);
  while (HAL_I3C_GetState(&hi3c2) != HAL_I3C_STATE_READY);
  HAL_I3C_Ctrl_IsDeviceI3C_Ready(&hi3c2, DYN_ADDR[i], 300, 1000);
}
// 完成后所有 5 颗 IMU 已各自有不冲突动态地址
```

注：ST 提供的 `HAL_I3C_Ctrl_DynAddrAssign` 用于 ENTDAA 广播（IMU 不带 48-bit PID 时不适用）。ISM6HG256X 多颗共总线的标准做法**不是 ENTDAA**，而是上面这条 Direct_SETDASA + TA0 GPIO 选通。

### 3 个核心 API 一句话

- `HAL_I3C_Init(&hi3c)` — 写 CFGR/TIMINGR，设 OD/PP 时钟分频，不发任何总线信号
- `HAL_I3C_AddDescToFrame(..., Direct_SETDASA, ...)` + `HAL_I3C_Ctrl_TransmitCCC_IT()` — 组装并发出 SETDASA CCC 帧，每个 IMU 调一次
- `HAL_I3C_Ctrl_Transmit_IT` / `_Receive_IT` / `_MultipleTransfer_IT` — 动态地址赋完后的常规 private data 读写

## stm32duino + I3C 在 sketch 里的关键陷阱

1. **`__HAL_RCC_PWR_CLK_ENABLE()` 必须在 `HAL_Init()` 后自己再调一次解锁 PUCR latch**，否则 `HAL_PWREx_EnableI3CPullUp` 静默失败
2. **不能同时 `Wire.begin()` 在同一对 GPIO** — Wire 抢 AF 到 I2C，I3C AF6 被覆盖
3. stm32duino 默认 `SystemClock_Config()` 不自动开 I3C 时钟门、不切 PB13/14 到 AF6、不碰 PWR_I3CPUCRx —— 全靠 sketch setup() 里自己写

## Win 下 ST-LINK firmware upgrade（对照 5-17 Mac 卡点）

- STM32CubeProgrammer Win 版本**不依赖 libusb-1.0**（那是 Linux USB driver）
- ST-LINK V3 自 Win10 起免驱
- Mac 上的 libusb pipe stalled 跟 Win 无关，**不会重现**
- 仍有 anecdotal `LIBUSB_ERROR_PIPE` 案例，标准修法："装 STSW-LINK009 + STM32CubeProgrammer 跑一次 firmware upgrade"

**Win 跑前 checklist**：
1. 装 STSW-LINK009 驱动
2. STM32CubeProgrammer GUI 跑一次 ST-LINK firmware upgrade（如果 Nucleo 出厂固件旧）
