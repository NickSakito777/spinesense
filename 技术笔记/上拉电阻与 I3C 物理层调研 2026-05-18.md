# 上拉电阻与 I3C 物理层调研（2026-05-18）

> 由 3 个独立 agent 并行 fetch 官方 datasheet / MIPI spec / STM32 HAL 源码完成。重点是把"为什么需要 SDA/SCL 上拉、Nucleo 和商业版到底有没有、STM32U385 有没有内置替代方案"这三件事一次性钉死。

## 一句话结论

I²C / I3C 物理协议层**硬要求** SDA/SCL 有 pull-up。Nucleo-U385RG-Q 板上和 STEVAL-MKI248KA 套件**都不提供**外部 pull-up；但 STM32U385 MCU 自身**内置 I3C dedicated pull-up**（PWR_I3CPUCR1/2 寄存器，AN5879 官方推荐做法），固件启用即可。SpineSense 定制拓展板 spec 仍决定**板上贴 SDA/SCL 0402 SMD 上拉电阻**（β=g）作为主路径，internal pull-up 同时启用作冗余。

---

## 1. 硬件现状

### 1.1 NUCLEO-U385RG-Q（MB1841E）

**结论**：板上 Arduino D14/D15（SDA/SCL）线路**没有集成 pull-up 电阻**。

**证据**：
- UM3062 Table 16（MB1841E variant, page 34）：D14/D15 仅通过 SB42-SB45 路由到 PB6/PB7 (I²C1) 或 PB13/PB14 (I3C2)，无 pull-up 列
- UM3062 Table 19：SB9/SB10/SB11 均与 SDA/SCL pull-up 无关
- UM3062 修订表 E01："To support I²C/I3C compatible (ARDUINO D14/D15)" —— 只加信号路由不加 pull-up
- ST wiki AN5879 + ST Community 共识：Nucleo 系列不集成 I²C pull-up

### 1.2 STEVAL-MKI248KA 套件

**结论**：套件本身（IMU 方板 + DIL24 adapter）**完全没有 SCL/SDA 上拉电阻**。Schematic 直读 100% 确认。

**证据**：
- **STEVAL-MKIGIBV5 (DIL24 adapter)**：R1 = 0Ω（OCS 线串联，NOT MOUNT）、R2 = 0Ω（INT2 线串联）、C1/C2 = 330pF（VDDIO/VDD 滤波）。SDA/SCL 是从 J1 到 JP2 pin 20/21 的纯导线，无任何元件
- **STEVAL-MKI248AA (IMU 方板)**：U1 = ISM6HG256X、C1 = 100nF、C2 = 2.2µF、C3 = 100nF、三个 header。**全板无任何 R designator**
- Data brief 原文（page 1）："comes ready-to-use with the required **decoupling capacitors** on the VDD power supply line" —— 仅承诺去耦电容，无 pull-up 承诺

---

## 2. 协议层为什么必须有

### 2.1 I²C 的硬要求

NXP UM10204 §3.1.1 原文：
> "Both SDA and SCL are bidirectional lines, connected to a positive supply voltage via a current-source or pull-up resistor."

I²C 是 open-drain 总线，slave 和 master 都只能下拉。**没有 pull-up 物理上无法回到 High 电平**，整条总线锁死。

### 2.2 I3C 的硬要求

I3C 分两种工作模式，**两种都不能没有 pull-up**：

- **Open Drain 模式**（Start condition / Address Header / ACK / SETDASA / ENTDAA / Hot-Join / IBI 仲裁）：与 I²C 同性质，需要 OD pull-up。MIPI I3C FAQ 原文：Controller 必须 *"Manage its Pull-Up structures, including the Open Drain class Pull-Up and High-Keeper Pull-Up for both SDA and SCL"*
- **Push-Pull SDR 数据阶段**：SCL 永远是 push-pull（这是 I3C 不支持 clock stretching 的根本原因）；SDA 在 Read T-bit 间隙是 high-Z，需要 **High-Keeper（弱 pull-up）** 维持电平
- **Bus Idle 态**（MIPI I3C v1.x §5.1.2）+ Hot-Join / IBI 触发：要求 SDA + SCL 都为 High → 必须 pull-up

I3C OD pull-up 典型几十 kΩ，比 I²C 的 1-10 kΩ 弱，因为高速段由 push-pull 提供边沿。

## 3. 没有上拉电阻的物理后果（按时间线）

1. 上电后 SDA/SCL high-Z，**bus 进不到 Idle 态**
2. Start condition 需要 SDA 在 SCL High 时下降 —— SCL 抬不起来，**Start 物理不成立**
3. SETDASA 的 ACK bit 释放后需要被 pull-up 拉高 —— 浮空，**Controller 判定为 NACK**
4. Read T-bit 间隙 SDA 是 high-Z —— **电平崩塌，读数据错位**
5. Hot-Join / IBI 触发依赖 Bus Idle —— **事件永远触发不了**
6. Wired-AND 仲裁失效 —— **多颗 SETDASA + GPIO 切 TA0 在 ACK 步骤集体失败**

---

## 4. STM32U385 内置 I3C dedicated pull-up（**关键新发现**）

**结论**：STM32U385 在 PWR 块提供 **I3C 专用 pull-up**（不是普通 GPIO 40 kΩ 弱 pull-up）。AN5879 官方推荐用 internal pull-up，不用外部电阻。

### 4.1 寄存器

| 寄存器 | 位置 | 用途 |
|---|---|---|
| `PWR_I3CPUCR1` | PWR 块 offset 0xB0 | 一组 I3C 候选 pin 的 pull-up enable bit |
| `PWR_I3CPUCR2` | PWR 块 offset 0xB4 | 另一组 |
| `I3C_CFGR.HKSDAEN` | I3C 块 bit 5 | High-Keeper on SDA，Read T-bit 间隙辅助保持器 |

**候选 pin（PWR_I3CPUCR1）**：PB6 / PB7（即 I3C1_SCL/SDA on Arduino D15/D14），以及 PA1 / PA6 / PA7 / PB2 / PB8 / PB9 / PB10 / PB12-14 / PC0 / PC1 / PD12 / PD13 / PG7 / PG8 / PG13 / PG14 / PH3 等。

### 4.2 HAL API

```c
HAL_PWREx_EnablePullUpPullDownConfig();     // 先解锁 latch 写入
HAL_PWREx_EnableI3CPullUp(PWR_I3CPU_PB13);  // SCL: 启用 PB13 的 I3C pull-up
HAL_PWREx_EnableI3CPullUp(PWR_I3CPU_PB14);  // SDA: 启用 PB14 的 I3C pull-up
```

CubeMX 的 I3C peripheral 配置页 + PWR 页都暴露这两项。

### 4.3 阻值

- 固定阻值，估算 **1.5-2.2 kΩ** 量级
- 是**强 I3C 专用上拉**，不是 weak keeper
- DS14598 datasheet Section 7 "I3C characteristics" 表有精确典型值（Fox 5-20 拿到 Win + Nucleo 后建议核对）

### 4.4 ST 官方明确推荐

- **AN5879** CubeMX 配置截图明确标注 "no pull is needed" —— 用 internal I3C pull-up 就不需要外部
- ST wiki "Getting started with I3C" 同样说明 STM32H5/U3/N6 I3C IP 集成 dedicated pull-up

### 4.5 5 颗 IMU + 60 cm 总线 rise time 估算

按公式 `t_rise = 0.8473 × R × C`，bus capacitance 估算 100-145 pF：

| RPU | bus C | t_rise | I3C OD spec 限 ~150 ns |
|---|---|---|---|
| 2 kΩ（estimated internal） | 100 pF | 170 ns | 略超 |
| 1.5 kΩ | 100 pF | 127 ns | 通过 |
| 2 kΩ | 145 pF | 246 ns | 超 |
| 50 kΩ（只剩 HKSDAEN 弱保持器） | 100 pF | 4.2 µs | 完全不行 |

**结论**：60 cm + 5 颗是 I3C 偏长拓扑，STM32 internal pull-up **理论够用但 marginal**，bring-up 时必须示波器看 SCL/SDA rise edge 确认。

## 5. "之前单颗能用 / 多颗失败" 的原理

**单颗能用是侥幸 marginal operation，不是真稳定**。机制：

1. **STM32 普通 GPIO 默认 weak pull-up ~40 kΩ** 在你不知情时一直在帮忙拉高总线（注意：这**不是** PWR_I3CPUCR 专用 pull-up，是 GPIO 默认 weak pull-up，强度差一个量级）
2. **I3C 启动握手用 OD 模式**（依赖 pull-up）—— 这一段 marginal 但侥幸通过
3. **握手完成进入 push-pull SDR 数据阶段**，MCU 主动驱动两电平 —— rise time 不再受 RC 限制，**掩盖 OD 段的 marginal 状态**

### 计算

| 场景 | bus C | RPU（普通 GPIO 40 kΩ default） | t_rise | spec 评价 |
|---|---|---|---|---|
| **单颗 + < 10 cm 飞线** | 25 pF | 40 kΩ | 847 ns | I²C Standard 1000 ns 内勉强通过；**I3C 完全爆** |
| **5 颗 + 60 cm** | 145 pF | 40 kΩ | 4.9 µs | 超 Standard 5 倍；**I3C 不可能** |

**单元电容参考**：
- I²C/I3C 器件每 pin（SDA 或 SCL）：spec 上限 10 pF，实测 sensor 5-10 pF
- 杜邦线 / 飞线：~1 pF/cm
- PCB trace 带地平面：1-2 pF/cm
- STM32 pin + package：约 5 pF

**结论**：任何超过单板单颗的场景都必须装专用 pull-up（STM32U385 PWR_I3CPUCR ~2 kΩ 或外置 1-2.2 kΩ）。

---

## 6. SpineSense 拓展板的最终决定

**β 决策（5-17 晚间 lock）**：在拓展板上贴 SDA/SCL 上拉 0402 SMD 电阻，拉到 VDDIO = 3.3V，阻值 **1-2.2 kΩ**（设计师按总线长度 + 信号完整性选具体值）。

**理由**：
- STM32U385 PWR_I3CPUCR internal pull-up 理论可替代外部，但 60 cm + 5 颗是 marginal 拓扑（见 §4.5 估算 170-246 ns 接近/略超 I3C OD spec）
- 板上贴电阻 = 物理上靠近总线终端，rise time 更稳
- 出厂即贴比"留焊位后焊"省一步实测
- 即使 internal pull-up 也启用 → 两个 pull-up 并联 → 等效阻值更小 → rise time 更稳

**固件侧仍需启用 internal pull-up**：因为 PWR_I3CPUCR 是 ST 官方推荐 + 也作为冗余保险。
