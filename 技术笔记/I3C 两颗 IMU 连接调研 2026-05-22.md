# Two-IMU I3C Connection Research 2026-05-22

## Conclusion

Two STEVAL-MKI248KA boards can share one I3C SCL/SDA bus. Do not use ENTDAA for the first round; use **SETDASA**. Fix the two `TA0/SA0/SDO` pins at different levels:

| IMU | TA0/SA0/SDO | Static address | Suggested dynamic address after SETDASA |
|---|---|---:|---:|
| IMU_A | GND | `0x6A` | `0x32` |
| IMU_B | 3V3/VDDIO | `0x6B` | `0x33` |

This is more reliable than setting both TA0 pins to 3V3 and relying on ENTDAA to discover the devices. The ISM6HG256X datasheet explicitly supports `SETDASA 0x87`, which assigns dynamic addresses through static addresses `0x6A/0x6B`. Earlier project records also document that ENTDAA with multiple devices of this same model can stall during PID arbitration.

## Two-IMU wiring

| Nucleo-U385RG-Q | IMU_A DIL24 adapter | IMU_B DIL24 adapter | Explanation |
|---|---|---|---|
| `3V3` | `JP1 pin 1 VDDIO` + `JP1 pin 2 VDD` | Same as IMU_A | Supply both boards in parallel |
| `GND` | `JP2 pin 13 GND` | Same as IMU_A | A common ground is required |
| `D15 / PB13` | `JP2 pin 20 SCL` | Same as IMU_A | I3C2_SCL, parallel bus connection |
| `D14 / PB14` | `JP2 pin 21 SDA` | Same as IMU_A | I3C2_SDA, parallel bus connection |
| `GND` or MCU GPIO driven low | `JP2 pin 22 SDO-SAO / TA0` | - | IMU_A static address `0x6A` |
| `3V3` or MCU GPIO driven high | - | `JP2 pin 22 SDO-SAO / TA0` | IMU_B static address `0x6B` |
| Not connected | `JP2 pin 14 INT1`, `pin 15 INT2` | Same as IMU_A | Interrupts are not needed for the first data-reading test |
| Not connected | `JP2 pin 19 CS` | Same as IMU_A | CS is pulled up by default, allowing I2C/I3C mode; manually connect it to 3V3 if problems occur |

## Test sequence

1. IMU_A alone: TA0=GND. Confirm `0x6A -> 0x32` and read `WHO_AM_I`.
2. IMU_B alone: TA0=3V3. Confirm `0x6B -> 0x33` and read `WHO_AM_I`.
3. Power both boards together on the parallel bus. First send SETDASA to `0x6A` to assign `0x32`, then send SETDASA to `0x6B` to assign `0x33`.
4. Poll acceleration/gyroscope XYZ from `0x32` and `0x33`; print two lines or one CSV line in Serial Monitor.

## Deciding whether external pull-up resistors are needed

The STEVAL-MKI248KA adapter itself does not provide strong SCL/SDA pull-ups. For the first round, try the STM32U385 dedicated internal I3C pull-up. If connecting both boards produces NACKs, intermittent read failures or gaps in serial data, temporarily add the following near the Nucleo end of the bus:

| Line | Resistor |
|---|---|
| SCL -> 3V3 | `2.2 kΩ` or `1.5 kΩ` |
| SDA -> 3V3 | `2.2 kΩ` or `1.5 kΩ` |

Do not solder them permanently at the outset. Verify the arrangement using a breadboard or removable wiring first.

## What changes when expanding to three or more IMUs

Two devices can be distinguished by setting one TA0 high and the other low, because exactly two static addresses are available. There is no third static address for three or more devices, so a multi-device approach is required:

- Route each TA0 independently to an MCU GPIO. Sequentially place the target IMU at `0x6A` or `0x6B`, then apply SETDASA.
- Alternatively, provide independent VDD/VDDIO power switching for each IMU; power and assign dynamic addresses to the devices one at a time.
- The final five-IMU garment bus should not short every TA0 to the same 3V3/GND connection.

## Supporting information

- ST data brief: STEVAL-MKI248KA is a DIL24 adapter kit exposing the complete ISM6HG256X pinout.
- ST schematic: `JP1 pin 1/2 = VDDIO/VDD`; `JP2 pin 13/20/21/22 = GND/SCL/SDA/SDO-SAO`.
- ST AN6353: `TA0` is the I2C device-address LSB and the MIPI I3C static-address LSB; `SCL/SDA` form the main I2C/MIPI I3C interface.
- ISM6HG256X datasheet: the I3C target supports `ENTDAA` and `SETDASA 0x87`; `SETDASA` assigns dynamic addresses through static addresses `0x6B/0x6A`.
